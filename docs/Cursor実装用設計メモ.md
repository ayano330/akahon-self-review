# 赤本セルフチェック 設計引き継ぎメモ
## 2026年10月28日時点・壁打ち結果

### 1. ツールの目的

高校3年生が大学入試の過去問（赤本）を解いたあと、自分の失点原因を選択式で入力し、次の赤本までに取り組む具体的な行動目標を決めるツール。

先生が普段の授業で生徒に伝えている指示を再現したい。

最も大切なのは、次の2点。

- 生徒が「次に何をすればよいか」を迷わず決められること。
- 「先生にやらされた」のではなく、「自分で選んだ」という感覚を持てること。

ただし、勉強が苦手な生徒は自分で学習計画を作れない可能性がある。そのため、適切な選択肢は先生側が用意し、生徒はその中から選ぶ。

### 2. 全体の設計方針【決定済み】

1. 生徒の赤本の失点理由に応じて、ツールが次のアクションを提案する。
2. 教材を選ばせる場合は、原則として候補を2〜3種類に絞る。
3. 教材候補に原則として優先順位をつけず、生徒自身が選ぶ。
4. 選択が完了したら、最終画面には選んだアクションを1本だけ表示する。
5. 生徒が選択または宣言した行動目標を設定して終了する。
6. 「最初の一歩」という独立項目は廃止する。
7. 「1日に生物に使える時間」の質問は撤廃する。
8. 学習時間の少なさを理由に、本来必要なアクションを省略しない。
9. アクションは複数日に分けて取り組んでもよい。
10. 問題演習の量は原則として生徒自身が決める。
11. 新しい教材を購入させず、現在配布している教材を活用する。
12. 生徒に表示する指示は短く、具体的でわかりやすい文章にする。
13. 各アクションは原則3ステップ以内とする。
14. 生徒への質問は必要最小限にし、現状の回答から判定できることは質問を増やさない。
15. 同じ入力には同じ結果を返す。AIによる自由な指示生成ではなく、決められた条件に基づく判定を基本とする。

### 3. 使用可能な教材

- 授業ノート：授業内容をまとめたノート。
- 授業動画・e-step：授業内容を再確認するためのもの。利用できるかどうかは生徒や授業によって異なる可能性がある。
- ミニテ集：授業で扱ったミニテストをまとめた冊子。1回15分程度。
- 単元別問題集 ★1〜3：宿題で扱った基礎〜標準レベル。
- 単元別問題集 ★4・5：より難しい問題。
- 論述問題集：論述の定番問題を収録。
- 演習教材：各先生がクラスに合わせて配布したプリント。
- 入試実戦演習：標準・発展の2種類。
- 解いた赤本：問題、解答、解説を使用。
- バイテク演習：遺伝子の発現の演習教材。

※教材の存在と、実際にどのアクションで使用するかは区別する。ここに記載された教材をすべて自動提案するわけではない。

# 4. タグ別アクション

## ① 理解不足【仮確定】

### 対象となる失点理由

現状の質問分岐では、以下の回答が該当する。

- 用語は言えるが、仕組みがわかっていなかった。
- 論述で何を書けばいいかわからなかった。
- 計算の解き方がわからなかった。

### 基本のアクション

**タイトル：** わからなかった内容を確認し、自分で説明できるようにしよう。

**なぜ：** 内容を確認したあと、自分で説明したり問題を解いたりして確かめるため。

**やり方：**

1. 授業ノート、または授業動画・e-stepで、間違えた内容に関係する部分を確認する。
2. 提示された教材の問題を解くか、口に出して説明するか、該当する選択肢から取り組み方を決める。
3. 問題演習なら正解して解き方も説明できるか、口頭説明なら何も見ずに最後まで説明できるか確かめる。

**目安：** 問題演習の量は生徒自身が決める。時間は未指定。

**終わりの目印：** 選んだ問題を正解し、解き方も説明できた。または、資料を見ずに最後まで口頭説明できた。

### 失点理由ごとの教材自動提案

| 失点理由 | 提示する候補 |
|---|---|
| 用語は言えるが仕組みがわからない | ミニテ集／単元別問題集★1〜3 |
| 論述で何を書けばいいかわからない | 論述問題集／口頭説明 |
| 計算の解き方がわからない | 授業で扱った演習教材／単元別問題集の既習問題 |

補足事項：

- 授業ノートと授業動画・e-stepは、内容を確認し直すための対等な選択肢。
- 動画を見る場合は、間違えた内容に関係する部分だけを見る。
- 口頭説明をする場合は、ノートを閉じて説明する。
- 計算問題では、該当単元の以前解いた問題から生徒自身が選ぶ。
- 論述問題集と口頭説明は対等におすすめする。
- 教材の選択肢に一律の優先順位をつけない。

### 未確定・要整理

確認用教材と問題演習・口頭説明の選択を、画面上でどう組み合わせるかの細部は未確定。

「仕組みがわからない」場合のミニテ集と単元別問題集の具体的な出し方も、Cursor実装時に整理が必要。

## ③ 考察(実験・グラフ)【仮確定】

**タイトル：** 考察問題を振り返り、次に同じような問題が出たときの解き方を決めよう。

**なぜ：** 今回の答えを確認するだけでなく、次に似た問題を解くときに使える方法を見つけるため。

**やり方：**

1. 授業で扱ったことがある問題なら、その教材に戻る。初見の問題なら赤本の解説を読む。
2. なぜその解答になるのか、自分で説明できるようにする。
3. 次に似た問題が出たとき、どこに注目し、どのように読み、どんな順番で考えるかを決める。

**目安：** 次への一手を1つ。

**終わりの目印：** 解答の理由を説明でき、次に使う具体的な解き方を1文で入力できた。

### 実装する入力

「次に同じような問題が出たら、どう解く？」

自由入力欄を用意し、生徒が具体的な行動を1文で入力する。

ここで求めるのは抽象的な反省ではなく、手の動かし方・読み方・考える順番などの具体的な行動。

入力例（説明用・未採用）：

## ④ 論述【採用済み】

失点理由によって指示を変える。

### A. 必要な要素・キーワードが足りなかった場合

**タイトル：** 論述で足りなかった要素を確認し、次に書けるようにしよう。

**なぜ：** 以前解いた問題なら解き直し、初見なら模範解答との比較で不足した要素を確認するため。

**やり方：**

1. 「今までの教材で同じ・似た問題に出会ったことがある？」と質問する。
2. 「ある」なら、該当する教材の問題を解き直す。「ない」なら、自分の答案と模範解答を比較して足りなかった要素を確認する。

**目安：** 未指定。

**終わりの目印：** 初見の場合は、足りなかった要素を挙げられること。既習問題の場合の解き直しの終了条件は未指定。

注意点：

「同じ・似た問題に出会ったことがある？」という質問は、論述問題集だけに限定しない。

ミニテ集、単元別問題集、演習教材など、今まで使用した教材すべてが対象。

### B. 字数制限に収めようとして時間を浪費した場合

現状の「字数に収められなかった」という選択肢は、先生の意図に合わせて変更したい。

**なぜ：** 説明の流れをつなぐために必要な内容が、論述の加点ポイントになるから。

**やり方：**

1. 解答に入れるべき要素を箇条書きにする。
2. 要素同士のつながりを、矢印などを使った簡単なフローチャートにする。
3. 必要な要素と説明の流れを確認してから答案を書き始める。

**目安：** 未指定。

**終わりの目印：** 必要な要素の箇条書きとフローチャートを作り、それを確認して答案を書けた。

重要な指導意図：

**なぜ：** 時間を使いすぎた場面を確認し、次の赤本で同じことを繰り返さないため。

**やり方：**

1. 赤本を振り返り、どの問題で時間を使いすぎたか確認する。
2. 時間が足りなくなった原因を考える。
3. 次の赤本で変える具体的な行動を1つ決める。

**目安：** 対策を1つ。

**終わりの目印：** 時間不足の原因を挙げ、対策を1文で入力できた。

### 実装する入力

生徒が次の赤本で変える行動を1文で自由入力する。

解く順番、時間配分、問題を後回しにする判断などは対策の例だが、すべての生徒に一律に指示しない。

---

## ⑧ 目だった課題なし【今回の回答で確定】

**タイトル：** 今回うまくいったことを1つ見つけよう。

**なぜ：** うまくいった行動を振り返り、次の赤本でも活かせるようにするため。

**やり方：**

1. 今回の赤本で、うまくいった行動を1つ思い出す。
2. その行動を次の赤本でも続けるか考える。

**目安：** 振り返る行動を1つ。

**終わりの目印：** うまくいった行動を1文で入力できた。

### 実装する入力

生徒がうまくいった行動を1文で自由入力する。

新しい課題を無理に作らない。次の赤本で同じ得点を取ることを目標として強制しない。

# 5. 既存の質問分岐から変更する点

元の `question-flow.md` は、2026年10月26日時点の `v3.html` の挙動を記録したファイル。

以下は今回の壁打ちで変更が決まった内容。

### 変更1：学習時間の質問を撤廃

現在の画面④「1日に、生物に使える時間はどのくらいですか？」を削除する。

30分・1時間・2時間以上によるアクションの分量変更も廃止する。

アクションは複数日に分けてもよいが、学習時間の申告によって必要な指示を削らない。

### 変更2：「最初の一歩」を廃止

結果画面に「最初の一歩」という独立項目を表示しない。

最終的に生徒が選んだ行動目標、または自分で宣言した行動目標を表示する。

### 変更3：教材の自動提案

志望校や所属クラスだけで教材を振り分けない。

既存の問題形式と失点理由を利用する。

判断できないことを勝手に推測しない。

理解不足では、確定した失点理由別の教材候補を活用する。

### 変更4：既習・初見の区別

考察問題では、授業で扱った問題か、初見の問題かによって復習方法を変える。

論述の要素不足では「今までの教材で同じ・似た問題に出会ったことがある？」という質問を追加する方針。

この質問は教材を論述問題集に限定しない。

### 変更5：論述の失点理由の文言

「字数に収められなかった」は、先生の意図としては「字数制限に収めようとして時間を浪費した」に近い。

表示文言を見直すこと。

ただし、これによって既存のタグ判定が変わるかどうかは、現在のコードと照合して確認する。

### 変更6：自由入力による宣言

以下のタグでは、行動目標や振り返りを1文で入力する。

- 考察(実験・グラフ)：次への一手
- 計算・処理：同じミスを防ぐ対策
- ケアレス：読み間違いなどを防ぐ対策
- 時間不足：次の赤本で変える行動
- 目だった課題なし：今回うまくいった行動

知識不足では、8割・9割の目標を選択して宣言する。

### 変更7：未習タグは作らない

生徒は全範囲を履修してから赤本を解く前提。

「未習・未対策」というタグは使用しない。

現在の質問に残っている「習っていない」という回答と、それに関係する優先判定も見直す。

最終的に扱うタグは以下の8つのみ。

理解不足 / 知識不足 / 考察(実験・グラフ) / 論述 / 計算・処理 / ケアレス / 時間不足 / 目だった課題なし

# 6. 未確定事項と実装上の注意

以下は勝手に仕様を決めないこと。

1. 「理解不足」の確認用教材と演習方法を画面上でどう組み合わせるか。
2. 「考察」の既習・初見を、既存の入力だけで判定できるか。追加質問の設置場所は未確定。
3. 「論述」で既習問題を解き直した際の具体的な終了条件。
4. 「知識不足」で復習後どの程度の間隔を空けるか。
5. 「字数制限に収めようとして時間を浪費した」という回答と、既存の「時間不足」タグとの優先判定。
6. 複数の失点理由が同時に記録された場合の、アクション選択と表示方法の細部。
7. 行動目標の自由入力欄の保存形式や文字数制限。
8. 授業動画・e-stepが利用できない生徒への表示方法。

これらは設計上の未確定事項として明示し、先生の承認を得るまで新たな指導方針を補わないこと。

# 7. Cursor / Workへの依頼

この設計メモは、これまで先生とChatGPTが壁打ちして決めた内容をまとめたもの。

次の作業を依頼する。

1. 現在の `question-flow.md`、既存のアクション定義、教材定義、実装コードを確認する。
2. 今回確定したルールと、現在の実装との差分を整理する。
3. 採用済み・仮確定・未確定を区別する。
4. 実装のために不足している情報があれば、重要なものだけ質問する。
5. 既存機能を勝手に削除せず、変更が必要な箇所を説明する。
6. 指導内容や教材の推奨ルールを新しく創作しない。
7. 先生が確認して承認してからコードに反映する。

最終的な目標は、生徒が赤本の失点原因を入力すると、先生が実際に言いそうな具体的な指示が提示され、自分が選んだ次の行動目標を宣言して終了できるツールにすること。

質問を増やすことや、複雑なシステムを作ること自体を目的にしない。
