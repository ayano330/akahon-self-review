作成日: 2026-10-22

## 1. 目的と前提

| 項目 | 内容 |
|---|---|
| 作りたいもの | 生徒にURLを配るだけで使える、赤本の自己分析ツール |
| 条件 | 無料 / AIの柔軟性を取り入れる / 決まった項目を質問する / 最後に「現状」と「次の赤本までにやること」を出す |
| 対象 | 高3の受験生。まず先生の担当科目の **生物** から。基礎クラスの生徒を主に想定 |
| 使う時期 | 赤本は冬期講習(12月下旬)から |
| 規模 | 30〜200人。1人あたり月に数回 |

### 一番の課題(先生が選んだもの)

**「振り返っても、次の行動に移さない」**(b2)

診断の精度や具体さを上げるだけでは、この課題には効かない。
「行動に移す」「続く」「忘れない」を支える仕掛けが必要。ここが設計の中心。

## 2. 設計の骨子(決まったこと)

### 2-1. 作りの方針

- **静的な1つのHTMLファイル**。サーバー・DB・ログインなし。Next.js 化は今は不要
- データは **生徒の端末のブラウザ(localStorage)だけ** に保存。保存は生徒がボタンを押したときだけ
- **判断はルール(プログラム)、語りと相談は任意でAI**
  - 同じ回答なら必ず同じ結果になる(先生が内容を確認できる)
  - 結果の文章は、AIではなくプログラムが固定の型にはめて作る
  - AIは、生徒が自分でプロンプトをコピーして自分のChatGPT等に貼るときだけ関わる。ツールからAIには何も送らない
- **AIなしで完結する**。AIアカウントを持たない生徒でも同じ価値を得られる
- 無料のホスティング(Cloudflare Pages、GitHub Pagesなど)に置く。Vercel Hobby は非商用限定なので避ける

### 2-2. 安全設計(配布の許可を取るための条件)

| 項目 | 方針 |
|---|---|
| 個人情報 | 氏名・学校名・ID・ニックネームの欄を作らない。志望校名と目標は任意で、端末内だけ |
| 保存先 | 端末のブラウザ内のみ。サーバーに送らない |
| アクセス解析 | 入れない |
| AIへの送信 | ツールからは送らない。生徒が中身を見てからコピーして貼る。ひとことの自由記述を含めるかは生徒が選ぶ |
| AIの利用 | 「アカウントがある人だけ」「塾が勧めているものではない」「保護者の了解のもとで」と明記 |
| 共有端末 | 「結果を消す」ボタンを置く |
| 提案の位置づけ | 「目安であり、先生に相談」と明記 |

静的サイトなので「情報が漏れる場所がない」と説明できる。

### 2-3. 質問票(7画面・約5分)

1. 何回目 / 得点・満点 / 志望校・年度・目標得点率(任意)
2. 時間(余裕 / ギリギリ / 手がつかなかった大問あり)
3. まだ習っていない・自信のない分野(複数選択)
4. 点を落とした設問(最大3つ): 形式 → 原因(形式で選択肢が変わる) → 失点の大きさ
5. 1日に使える時間(30分 / 1時間 / 2時間以上)
6. ひとこと(任意)

分野リスト、形式、原因の選択肢は `v2.html` 内の `FIELDS` `FORMS` を参照。

### 2-4. 判断ルール

- タグは8種類: 未習・未対策 / 理解不足 / 知識不足 / 考察 / 論述 / 計算・処理 / ケアレス / 時間不足
- 失点の重み: 大=3、中=2、小=1。時間「ギリギリ」+1、「手がつかなかった」+3、未習分野の選択+3
- 最大のタグが最優先、2番目が「余力があれば」
- 同点の優先順: 未習 > 理解不足 > 知識不足 > 考察 > 論述 > 計算 > ケアレス > 時間不足
- **未習が見つかったら、他より先に必ず最優先**(分野の選択でも、設問の原因「習っていない」でも)
- 使える時間が30分なら、ステップ1つだけ・余力の提案なし

### 2-5. アクションの型

「やること / やり方(3ステップ以内)/ 目安 / 終わりの目印」の4点セット。
加えて、2分でできる **「最初の一歩」** を各タグに用意(`ACTIONS` の `first`)。
基礎クラスの生徒が自分でアクションを作れない問題に対し、**作るのはAI/先生、生徒は選ぶ役** にする。

### 2-6. 行動を支える仕掛け(b2への対策)

| 仕掛け | 内容 | 状態 |
|---|---|---|
| 約束カード | いつ・どこまでやるかを生徒が決める | v2で実装済み |
| カレンダー登録(.ics) | 約束を生徒自身のカレンダーに入れ、通知はスマホに任せる | v2で実装済み |
| 実行確認 | 次に開いたとき、前回の約束を出して「やった/一部/できなかった(理由)」を聞く | v2で実装済み |
| 前回できなかった生徒への調整 | 次回の約束が自動で「最初の一歩(2分)」から始まる | v2で実装済み |
| 保留ゾーン | できなかった約束を一覧に残す。「小さくして再約束」「手放す」を選べる | v3で実装済み |
| 先生に見せる画面 | 履歴・約束・実行状況・保留数を一覧にした読むだけの画面 | v3で実装→第4弾で削除(ホームを一緒に見れば足りる) |

### 2-7. そのほかの機能

- **用語カード**: 問い・答えを入力。言えたら1日後・3日後・7日後に再登場、言えなかったらすぐ再登場(v2実装済み)
- **大学別の得点率の推移**: 志望校・年度・得点を入れると折れ線グラフ。目標得点率を点線で表示(v2実装済み)
  - 生物だけの合格最低点は公表されていない大学が多いので、「目標得点率」(先生と相談して決める)で代用
- **AIへの橋渡し**: 診断結果を前提にしたプロンプトを生成してコピー(v2実装済み)

## 3. 後回しにすること・やらないこと

| 項目 | 理由 |
|---|---|
| 管理者への自動送信(段階3) | 識別ID・同意・DB・個人情報の取り扱いが必要で、決裁が重い。段階1・2の効果が見えてから |
| 答案・問題の写真アップロード | 精度・費用・個人情報のリスク |
| 無料AI API(Gemini等)の実行時呼び出し | 無料枠の上限、入力データの学習利用、悪用対策が必要。後から足せる拡張に格下げ |
| ログイン | 匿名設計のため |
| Next.js 化 | 静的1ファイルで配布できるため、今は不要 |

### 段階の考え方(決裁との関係)

1. **段階1**(匿名・端末内だけ。いまここ): 決裁が軽い。まずここで効果を確かめる
2. **段階2**(生徒が選んで先生に見せる): 第4弾で画面は外した。ホームを一緒に見る運用に変更
3. **段階3**(自動送信): 重い。効果が確認できてから検討

## 5. 次にやること

### 5-1. v3 の作成(AIの作業)

先生のフィードバック(v2を触った感想)から決まったこと:

1. **約束の日時を柔軟に**
   - 「あとで決める」を選べる(日時なしで約束できる)
   - 選択肢に「3日後」「来週」を足す
   - 日付だけ決めて、時刻は任意

2. **約束の内容(量や言い回し)を、生徒が自分で書き換えられる**
3. **保留ゾーン**: トップに「保留中の約束 N件」。一覧に残し、「小さくして再約束」「手放す」を選べる。溜まることを責める見せ方にしない
4. **先生に見せる画面**: 履歴、約束、実行状況、保留数の一覧。読むだけ。トップから開ける
5. **未確認の約束が複数あっても、順に確認できる**(現状はトップに1件しか出ない)

- **結果**: 約束の「やること」の初期文を、選んだ教材・目標、または入力した次への一手に(手順は足さない。docs/question-flow.md)。右のボタンは「文を消す」。AIに相談は▼/▲で開閉、コピーするは右。「次に活かしたいこと」→「今回よかったところ」(保存済みのデータはそのまま引き継ぐ)。約束後は「約束カードに保存しました」だけ出し、続けて今回よかったところ。「保存してトップに戻る」を右下に
- **約束ページ**: 「保留中の約束 N件」→「未回答の約束があります」(▼で開き、再約束・手放す)。保留中=ホームで「未完了」と答えた約束で、期限切れ未回答ではない
- **演出**: 正答率が目標以上のとき、横にクラッカーと紙吹雪(1回だけ。動きを減らす設定では静止)
- 約束のアイコンは、先生が用意した指切りの画像をそのまま使用(白背景を透明にして埋め込み)

**第8弾(2026-10-30。実装済み。先生の確認を反映)**
- ヘッダーのロゴは、左(戻る)・右(メニュー)を同じ幅にして中央固定
- ホーム: 「記録する」を右に。約束カードの「めじるし」を削除(約束ページの一覧には残す)
- 点を落とした設問: 「設問を追加する」を右に。日本語の理由の例を「主語と述語・原因と結果がおかしい、てにをはがおかしい、用語の使い方がおかしいなど」に
- 考察の次への一手: 試験中にできない「口に出して解説する」をやめ、「グラフや表に線や丸をつけることで理解しやすくする」「読み取ったことを自分の言葉でメモしながら読む」に
- 結果: 「文を消して自分で書く」、「やること(編集できます)」、AIに渡す文章の注釈を削除。「いつやりますか?」に「次の赤本を解いているとき」を追加(日付なし。次の赤本の記録ができたあと、ホームで「達成できましたか?」を聞く)。これを選ぶと解き直しの質問は出さない
- 「2〜3日後の見直し」をやめ、「赤本の解きなおし、一週間以内にもう1回やる?」(やる / やらない、初期は「やらない」)に置き換え。「やる」なら、今日から7日後が期限の「赤本を解き直す」約束が別に1つ入る
- 各大学のページ: 「追加」を右に

**第9弾(2026-10-31。実装済み。単元の指定)**
- 知識不足(ミニテ集)と、理解不足で冊子の教材を選んだとき(口頭説明は除く)に、単元を指定できる。任意、3つまで。タップでリストが開く(docs/materials.md の15単元。冊子1〜4でまとめる)。同じ単元は2回選べない
- 約束の文に単元名を入れる(例: 「酵素・代謝・体液のミニテ集で9割以上取れるまで繰り返す」)。結果の「やること」の手順と、AIに渡す文章にも入れる。単元リストの「体液」は「体液(免疫を含む)」と表示(免疫は体液で扱う。恒常性ではない)
- AIに渡す文章に、目標の正答率と、今回との差(「あと◯ポイント」)を入れる。目標に届いていなければ「差を埋めるために何をすればよいかを大事に」とお願いする。大学名は入れない(名前・学校名を貼らない方針に合わせる)
- 約束に教材名が入るとき(知識不足、理解不足で教材を選んだとき)は、「次の赤本を解いているとき」を出さない。解く前に済ませることだから。再約束にも引き継ぐ

**第7弾(2026-10-30。実装済み。他の先生へのヒアリングを反映。詳細は `docs/teacher-survey-diff.md`)**
- 失点理由を4つ追加(ミニテ外の用語 / 日本語がおかしい / 初見の計算 / 指定の読み落とし)。タグは8つのまま
- アクションの細部: 知識不足に「全問正解」、理解不足の候補に「口頭説明」、論述の要素不足に「知識系か考察系か」、論述に「日本語の読み直し」アクション
- 考察・計算・ケアレス・時間不足の「次への一手」は、ひな形をタップで選ぶ(「自分で入力する」も可)。文は先生の赤ペン待ち
- 約束に、2日後・3日後の見直し(任意、別の約束として入る)。第8弾で「赤本の解き直し」に置き換え
- 見送り: 「捨てる」提案、志望校での出し分け、まぐれ正解の入力、AI の口頭判定

## 7. 決定の理由(経緯のメモ)

| 論点 | 決めたこと | 理由 |
|---|---|---|
| AIをどう使うか | 実行時のAIは任意のコピペ。判断はルール | 無料・安全・再現性。基礎クラスの生徒はAIの出力の質を判断できない |
| 台本づくり | AIが叩き台を作り、先生が赤ペン | ゼロから書くより、直すほうが楽 |
| 対象科目 | まず生物。質問は科目共通の構造にして、他科目に広げられるようにする | 先生の担当科目で検証するため |
| 管理者への送信 | 後回し | 安全設計と真逆で、決裁が重い。使う生徒に偏る限界もある |
| 約束の通知 | 生徒自身のカレンダーに任せる | サーバー・通知機能なしで「忘れる」に対応できる |
| 「全部やって初めて力が出る」 | 送信以外は段階1に全部入れる | 全部入りで決裁に出すと送信が目につくため、送信だけ分ける |

## 8. 用語

- **赤本**: 大学入試の過去問題集
- **ルール(ルールベース)**: 決まった条件で結果を出す方式。同じ入力なら同じ結果
- **localStorage**: ブラウザの中にデータを保存する仕組み。端末の外には出ない
- **.ics**: カレンダーに予定を入れるためのファイル形式
- **静的サイト**: サーバー側で処理をしない、ファイルを置くだけのサイト
- **決裁**: 教室長など、配布の許可を出す人の承認
